## Contract (tests and implementation both bind to this)

`database/outside_spending.py`
- `split_candidate_names(text) -> list[str]` — split on `,` `;` `/` `&` and the word `and` (case-insensitive), trimmed, empties dropped; a single name returns `[text]`.
- `candidate_name_key(text) -> tuple[str, str] | None` — strip `. , ' "`, upper-case, collapse whitespace; `(first_token, last_token)`; `None` when fewer than two tokens. `"J.B. Pritzker"` → `("JB","PRITZKER")`; `"Michelle N. Pierre"` and `"Michelle Pierre"` → `("MICHELLE","PIERRE")`; `"Rauner"` → `None`. Applied identically to `f"{first_name} {last_name}"` of an `isbe_candidates` row.
- `part9_cycle(day: date) -> int` — `year + year % 2`.
- `attribute_part9_rows(rows, candidates) -> list[dict]` — pure function. `rows`: dicts with `candidate_name`, `amount`, `expended_date` (date), `supporting`, `opposing` (+ passthrough keys). `candidates`: dicts with `key` (tuple), `cycles` (set[int] or `None` = no gate) + identity keys. Returns one dict per (row, matched candidate): the row's keys plus `candidate` (the candidate dict), `share` = amount / number of split names, `named_count`, `name_as_filed` (the matched part).
- `summarize(attributions) -> dict` — `total`, `support_total`, `oppose_total` (sums of `share`), `row_count`, `spender_count` (distinct `committee_id`).
- `get_candidate_outside_spending(conn, candidate_id, *, scope) -> dict | None` — reads `isbe_candidates` (name → key), `isbe_candidacies` (cycles), then `isbe_condensed_expenditures e LEFT JOIN isbe_committees c ON c.id = e.committee_id` with `e.d2_part LIKE '9%' AND e.archived = FALSE AND UPPER(regexp_replace(COALESCE(e.candidate_name,''), '[.,''"]', '', 'g')) LIKE '%<LAST>%'`, attributes in Python, and returns `None` when nothing attaches all-time, else `{"all_time": summary, "window": summary, "by_spender": [ {committee_id, committee_name, support_total, oppose_total, total, row_count} sorted by total desc ], "rows": [line items in the window, newest first]}`. Line item keys: `expenditure_id`, `expended_date`, `committee_id`, `committee_name`, `amount`, `share`, `named_count`, `supporting`, `opposing`, `purpose`, `payee`, `office_as_filed`, `candidate_name_as_filed`, `filed_doc_id`. The window is the page scope on `expended_date`; archived rows never count.

Race builder (`database/analytics.py` `_build_state_race_analytics_rows`, Part-9 block): same key/split/share rules via the module above; `is_supporting`/`is_opposing` read through `bulk_expenditures_clean` when the columns exist (`_column_exists`, else 0); the `race_filter` prefilter becomes `UPPER(regexp_replace(COALESCE(e.candidate_name,''), '[.,''"]', '', 'g')) LIKE ANY(?)` over the race candidates' last tokens (≤ 15, else no prefilter). `outside_spending_rows` items: `candidate_id` (as in `candidate_rows`: `''` when blank), `candidate_name` (canonical, from the candidacy feed), `support_total`, `oppose_total`, `total_amount`, `row_count`; sorted by total desc then name. `outside_spending_total` = Σ `total_amount` of those rows. Payload (supporting rows only) gains `outside_spending_window = {"date_from": "<iso>", "date_to": "<iso>"}` (the cycle window intersected with the page window).

### Contract — `database/name_normalize.py` and the `/search` matching (Phase 1; tests in `tests/test_search_names.py` follow it literally)

- `normalize_name(text) -> str`: upper-case; every character that is not `A–Z`, `0–9` or space becomes a space (so `-`, `.`, `,`, `'`, `"`, `&`, `/` all split tokens — hyphen = space, M1); whitespace collapsed; leading/trailing trimmed; `None`/blank → `""`. No reordering (token matching makes "Last, First" irrelevant for search; the Part-9 matcher keeps its own reversal rule).
- `name_tokens(text) -> list[str]`: the normalized string split on spaces, with generational suffix tokens (`JR`, `SR`, `II`, `III`, `IV`, `V`) **and single-letter tokens (initials)** dropped **from the query side only** while at least one multi-letter token remains (orchestrator decision 2026-10-29 on the tester's R1: a query's initial must not hide the records filed without it — "Michael Frerichs", "Michael W. Frerichs" and "Mike W Frerichs" find the same people; the stored name's own extra tokens never matter because only query tokens are required).
- `NICKNAMES: dict[str, tuple[str, ...]]` — one explicit map, first-token aliases both ways (e.g. `MIKE ↔ MICHAEL`, `TOM ↔ THOMAS`, `BOB/ROB ↔ ROBERT`, `BILL/WILL ↔ WILLIAM`, `JIM ↔ JAMES`, `DAN ↔ DANIEL`, `SAM ↔ SAMUEL/SAMANTHA`, `CHUY ↔ JESUS`, `JB ↔ JAY ROBERT`, `PAT ↔ PATRICK/PATRICIA`, `TONY ↔ ANTHONY`, `CHRIS ↔ CHRISTOPHER/CHRISTINE`, `LIZ/BETH ↔ ELIZABETH`, `KATE/KATIE ↔ KATHERINE/KATHLEEN`, `JOE ↔ JOSEPH`, `DAVE ↔ DAVID`, `STEVE ↔ STEVEN/STEPHEN`, `RICK/DICK ↔ RICHARD`, `ED ↔ EDWARD`, `TED ↔ THEODORE/EDWARD`, `JEFF ↔ JEFFREY`, `MATT ↔ MATTHEW`, `NICK ↔ NICHOLAS`, `ALEX ↔ ALEXANDER/ALEXANDRA`, `JEN/JENNY ↔ JENNIFER`, `SUE ↔ SUSAN`, `PEG/PEGGY ↔ MARGARET`). `expand_token(token) -> set[str]` = the token plus its aliases; applied to EVERY query token (any position).
- `search_tsquery(text) -> str | None`: for each query token an alternation of prefix lexemes `(mike:* | michael:*)` joined with `&`; `None` when no token remains. Lexemes are the normalized tokens lower-cased (the `simple` dictionary does no stemming). Example: `"Frerichs, Mike W."` → `frerichs:* & (mike:* | michael:*)` (the initial is dropped on the query side). A multi-word alias (`JB ↔ JAY ROBERT`) must still yield a tsquery PostgreSQL accepts — encode it as a parenthesised conjunction `(jb:* | (jay:* & robert:*))` or drop it from the map.
- `NAME_TSVECTOR_SQL(expr) -> str` = `to_tsvector('simple', regexp_replace(upper(coalesce(expr, '')), '[^A-Z0-9 ]', ' ', 'g'))` — the ONE server-side normalization, used verbatim in the predicates and in the GIN expression indexes (so the planner can use them): `idx_isbe_committees_name_tsv` on `isbe_committees` (ETL DDL), `idx_isbe_candidates_name_tsv` on `isbe_candidates` (`first_name || ' ' || last_name`), `idx_analytics_donor_summary_name_tsv` on `analytics_donor_summary.donor_name` (schema.sql), `idx_bulk_cand_cmte_finance_agg_name_tsv` on the candidate matview's `candidate_full_name` (`scripts/swap_bulk_to_isbe.py`), `idx_fec_candidate_match_name_tsv` on `fec_candidate_match.candidate_name`. A pattern test pins the five DDL strings as `tests/test_search_perf.py` does for the trigram index.
- `/search` sections (webapp/routes/main.py): predicate = `NAME_TSVECTOR_SQL(col) @@ to_tsquery('simple', ?)` with the query from `search_tsquery`; a section that returns zero rows for a query of ≥ 4 characters runs ONE substring fallback (`UPPER(col) LIKE '%' || normalize_name(q) || '%'`) with the same LIMIT, so mid-word fragments still work; numeric / key-like queries keep today's id paths (`tests/test_webapp.py:1922` stays green). The local candidate section reads `isbe_candidates` (first + last) UNIONed with the committee matview rows, so a candidate without a committee link appears (totals 0). Committees (S3): the name matches ∪ committees linked (`isbe_candidate_committees`, plus accepted `committee_family` members) to the candidates the candidate section matched, each marked `via_candidate = "<First Last>"`, de-duplicated by committee id, name matches first. #### Phase 2 scaffold (Fable, 2026-10-29 ~02:25Z — handed to the builder at P2-M2; names may follow the P2-M1 tests where they already exist, shapes are binding)

**A. `database/name_normalize.py` — the shared predicate helpers (new, beside the Phase 1 functions).**
- `token_match_sql(column_expr) -> str` = `f"{NAME_TSVECTOR_SQL(column_expr)} @@ to_tsquery('simple', ?)"` — one `?`, bind `search_tsquery(q)`. Used verbatim in every entity-table predicate so the GIN expression indexes match.
- `substring_pattern(query, *, min_len=4) -> str | None` = `'%' + normalize_name(query) + '%'` when the normalized query has ≥ `min_len` chars, else `None` (the `/search` rule; `webapp/routes/main.py::_substring_fallback_pattern` becomes a one-line alias of it or is left as is — no behaviour change to `/search`).
- `substring_match_sql(column_expr) -> str` = `f"UPPER({column_expr}) LIKE ?"` (the compat layer runs `LIKE` as `ILIKE`; the pattern holds only `A-Z0-9 ` so nothing the user typed is a wildcard). Bind `substring_pattern(q, min_len=…)`.
- `name_filters(column_exprs, query) -> list[tuple[str, list[str]]]` — the ordered WHERE variants a caller tries until one returns rows: `[(token_clause, [tsq]*n), (substring_clause, [pattern]*n)]` where the clause ORs the columns in `column_exprs` (a str or list); the substring variant only when `substring_pattern` is not `None`; `[]` when neither applies (caller then applies no name filter and returns nothing, as today for an empty query). Caller pattern: `for where, params in name_filters(cols, q): rows = run(where, params); if rows: break`. For a paged list run the COUNT with each variant first and stop at the first non-zero count; the rows statement reuses that variant. For `HAVING BOOL_OR(...)` compose with `token_match_sql('c.name')` inside the aggregate (expressions compose; the clause text is all that matters).
- Transactional tables (P2-2) use `substring_match_sql(col)` + `substring_pattern(q, min_len=2)` only (no token statement).
- `name_matches(query, label) -> bool` (Python side, Viz Lab P2-4): every `name_tokens(query)` token prefix-matches some token of `normalize_name(label).split()` directly or through `expand_token`; else `normalize_name(query)` (≥ 4 chars) is a substring of the normalized label; empty query → `True`.
- `canonical_first_token(token) -> str` (matcher M2): the representative of the token's alias component — `NICKNAMES` read as an undirected graph, components computed once at import (union-find or BFS), representative = the alphabetically smallest member; a token with no aliases → itself. Guarantees `MIKE`/`MICHAEL` agree and `TED`/`EDWARD`/`ED`/`THEODORE` agree. Known limitation to state in the docs: a multi-word alias (`JAY ROBERT`) is one member string, and a filing's first token is one word, so `JB` matches only records whose first token is `JB`.
