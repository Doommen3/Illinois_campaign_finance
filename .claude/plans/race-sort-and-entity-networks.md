## Findings (scout survey 2026-10-28, HEAD 9eb07a7)

**Ask 1 — why a header click only sorts 12 rows.**
- The overview builder `dashboard()` (`webapp/routes/analytics.py:632-740`) gets the full race list through `_get_state_race_rows` (`:543-563`, `limit=100000`; ~1,761 races in the largest cycle), which `get_state_race_analytics` (`database/analytics.py:3160`) sorts in Python (`:3181-3190`) by a whitelisted field; the overview keeps the first 12 (`:723-724`).
- The preview table (`webapp/templates/analytics/overview.html:96-140`) is a plain `table.data-table`, so `webapp/static/js/table_sort.js` (global, `base.html:167`) sorts the 12 DOM rows on header click. A separate GET select `state_race_sort` / `state_race_dir` (`overview.html:42-52`) re-requests the page with a server sort; the two mechanisms do not know about each other.
- Whitelist `_STATE_RACE_SORTS` (`webapp/routes/analytics.py:495`) = `total_amount`, `outside_spending_total`, `outside_pressure_ratio` only. The preview shows eight columns: Race, Candidates (cycle), Donors, Contributions, Total Amount, Outside Spending (E), Outside Pressure Ratio, Top Candidate Share (cycle).
- Cache cost today: `_overview_cache_key` (`:604-630`) and `_state_races_cache_key` (`:519-527`) both carry sort and dir, so the overview is fragmented 3×2 and every variant re-runs the whole race build (the builder takes no sort; `database/analytics.py:3170`). The warm script warms one variant.
- `/analytics/state-races/` (`:783-825`) renders all rows with no LIMIT (`state_races.html:27-50`, also client-sortable). No JSON endpoint serves the race list.

**Ask 2 — nothing per-entity exists.**
- The eight views Devin names are the tabs of `/analytics/networks` (`webapp/templates/analytics/networks.html:89-97`; route `webapp/routes/analytics.py:887`; `_networks_graphs` `:357`). Builders: `get_network_graph` (`database/analytics.py:1274`), `get_vendor_expenditure_network` (`:7018`), `get_lobbying_influence_graph` (`:5872`), `get_irs527_ecosystem_graph` (`:6442`), `get_state_federal_overlap_graph` (`:7206`). `/analytics/relationships` (`:1189`, `_relationships_graphs` `:430`): `get_donor_cogiving_network` (`:4741`), `get_committee_similarity_network` (`:5116`), `get_candidate_competition_networks` (`:5605`). **Every builder takes a window and limits only; none takes a committee, candidate or race.** Cached per window (`_networks_cache`, `_relationships_cache`, TTL 21600 s, `config.py:96-97`).
- The only entity-scoped network code is the uncached JSON API `/api/analytics/network/focus-sankey` (`webapp/routes/api.py:642`, inline SQL, `focus_node_id`, limits 15–20, max 100) behind the Custom Sankey tab, plus `/api/analytics/network/suggest` (`:498`).
- Candidate detail (`webapp/templates/candidates/detail.html`) and state race detail (`state_race_detail.html`) have tables and stat cards only. They carry 13 `scope_tag(` sites (4 + 9), all registered in `tests/scope_widgets_registry.py` (`:235-258`, `:646-692`); a new windowed tag needs a registry row (+ probe) or `test_every_windowed_tag_site_is_registered` fails.
- Payload contract shared by the existing graphs: `nodes [{id, label, node_type, region, total_amount?, …}]`, `edges [{source, target, edge_type, weight, count?, …}]`, `centrality` (top 100), `summary {node_count, edge_count}` (`database/analytics.py:1331-1352`, `:1503-1520`).
- Viz Lab (`webapp/routes/experimental.py`) is gated off in prod (`config.py:45`); its `network_slice` prototype is a Chart.js bar + tables, not a graph. Not a base for ask 2.

**Ask 3 — why the force graph is unreadable.**
- No graph library. Two hand-written renderers: `webapp/static/js/analytics_networks.js` (`layoutForce :426`, charge 3200–5000 by node count, zoom helper `:377`, generic renderer `:588`, reused by vendor `:1022`, overlap `:1194`, lobbying `:1219`, 527 `:1244`) and `webapp/static/js/relationship_graphs.js` (`layoutForce :367`, pairwise repulsion + spring, 260–280 iterations; `nodeRadius :175` = 5 + √(size+1)/12 clamped 4–18; `bindPanZoom :943`, wheel ×1.1/×0.9 clamped 0.7–3.2; labels only at zoom ≥ 1.4 `:1162`; also `drawArcGraph :1192`, `drawAlluvialGraph :1351`).
- No collision force, no label collision culling, no zoom-to-fit, no focus/dim, no legend-driven filtering. Client caps 90 nodes / 180 edges (relationships `:1704-1730`) and 180 / 320 with per-node caps (networks `:528-547`); server caps via SQL LIMIT + `edge_limit` (`database/analytics.py:1377, 4764, 5149, 5648, 5920, 7068, 7232`; route clamps `webapp/routes/analytics.py:126`, `:1193-1199`).
- d3 is already used from a CDN on `/lobbying/flows` (d3 + d3-sankey) and the Viz Lab state maps; nothing is vendored.
- Playwright is already a project dependency (scraper), so a headless render + overlap measurement is available locally as a verification tool.
