## Interpretation and decisions (journaled)

- **D1 Rows endpoint.** `database/entity_network.py::edge_rows(conn, payload, *, source, target=None, edge_type, date_from, date_to, limit=200)` returns `{"rows": [...], "total_amount", "total_count", "truncated": bool}` for the edges of the cached ego payload. Receipt edges (`donor_committee` 1A, `in_kind_donor_committee` 5A, `transfer_in` 2A) read `isbe_condensed_receipts` with exactly the predicates `_grouped` uses for that edge type and window (reuse the SQL fragments; the sum of the rows MUST equal the edge weight — that is the test). Vendor edges (`committee_vendor`) read `isbe_condensed_expenditures` the same way. Independent-expenditure and committee-candidate edges return `{"rows": [], "unsupported": true}` (Phase B). Row fields: `date`, `amount`, `d2_part` (or `purpose` for expenditures), `description` if the table has it (check the ETL's column list in `scripts/isbe_sunshine_etl.py`), `counterparty` (name as filed, redaction respected: no address fields ever), `committee_id`, `committee_name`, `filed_doc_id`, `filing_href` (`/committees/filing/<filed_doc_id>`). `target=None` means every entity committee the source connects to by that edge type (a member of the money-flow panel can touch several committees; its listed amount is the total). `source`/`target` MUST be node ids present in the payload (else `None` → 404); `edge_type` whitelisted; nothing from the request reaches SQL except through those lookups.
- **D2 Routes.** `/candidates/<int:candidate_id>/network/rows.json` and `/analytics/state-races/<race_key>/network/rows.json` in `webapp/routes/entity_analytics.py`, params `source`, `target` (optional), `edge_type`, plus the page's scope query (same `resolve_time_scope` call as `network.json`). Reuse the cached ego payload (same cache key as `network.json`), cache the rows result under `analytics_entity_network` with the params in the key, same TTL and `Cache-Control` as `network.json`; `?refresh_cache=1` gated the same way.
- **D3 UI.** `webapp/static/js/entity_views/focus_panel.js`: the member's "Rows" cell becomes a button ("6 rows"); click fetches rows.json (URL template from the page meta: add `rows_url` to `graph_meta` in the route and read it as `ctx.rowsUrl`), renders a nested table (Date · Amount · Type · Description/Purpose · Filing link) under the member, "Showing 200 of N" when truncated, second click collapses, errors show one line. Works for every member of money-flow aggregates and for vendor-network vendor panels; the ego view's "Connected to" list gets the same button per neighbour.
- **D4 Renderer.** Vendor d3 as ONE file `webapp/static/js/vendor/d3.v7.min.js` (`curl -fsSL https://cdn.jsdelivr.net/npm/d3@7.9.0/dist/d3.min.js`, record the version and sha256 in `webapp/static/js/vendor/README.md` with the ISC `LICENSE` text; if the download fails, stop and report). New `webapp/static/js/network_graph.js`: `window.NetworkGraph.render(container, {nodes, edges}, options)` — `forceSimulation` with link distance by weight rank, `forceManyBody`, `forceCollide(r + labelPad)`, deterministic (seed initial positions on a radial layout by role; run a fixed tick count synchronously, then set `data-settled="1"` on the svg), zoom-to-fit (d3.zoom transform computed from the bbox, min scale so the whole graph sits inside the container at load), semantic zoom (labels for the top-k nodes by `total_amount` at fit zoom, k from the current scale; every node has a `<title>` and shows its label on hover), click-to-focus with the existing contract (`focused`/dimmed classes, the `focus_panel.js` list, Escape/background/second click clear it), legend chips that filter node types (extend `graph_legend.js`'s `renderGraphKey(container, options)` with an `onToggle(nodeType, visible)` option if it has none; read lines 198–234 first), linked table: the Network tab's edge table rows get `data-source`/`data-target` and clicking a row focuses its node, focusing a node highlights its rows. `ego_force.js` keeps its container, data contract and N19 behaviour but delegates drawing to `NetworkGraph` when `window.d3 && window.NetworkGraph` exist (the radial code stays as the fallback). Load the two scripts in `webapp/templates/entity/network.html` before the view scripts with new `v=` values. CSS in `webapp/static/css/style.css` (own class prefix `ng-`).
- **D5 N8 probe** `tests/integration/test_network_graph_readability.py`, `@pytest.mark.integration`, Playwright sync API (installed: 1.58, chromium present), viewport 1200×700, base URL `os.environ.get("PROBE_BASE_URL", "http://127.0.0.1:5053")`, pages `/candidates/13505/network?view=ego` and one state race network page with `?view=ego` (pick a race with ≥ 20 nodes from local data). Wait for `svg[data-settled="1"]`. In-page checks: (i) zero intersections among visible label bboxes, (ii) zero circle overlaps (distance < r1 + r2), (iii) graph bbox inside the container, (iv) every visible label font-size ≥ 11 px, (v) hovering an unlabeled node makes its label visible. **Run it first against the current renderer and record the five counts as the baseline in this plan's log** (Devin asked for that measurement); then make it green.
