## Devin's ask (verbatim, to-do item 1)
> On the website, for example if looking at a candidate detail page and on the networks button, sometimes the money flow will show top 28 individual donors, ie for michael w frerichs. I want there to be a way to disaggregate this or to click and be able to see who is in that 28, or what the in kind contributions are etc. Whenever a money flow is a group of more than 1 item, I want to be able to easily click and see what is included in that flow, and we should also consider whether nodes on other pages should have this same behavior and we should implement it if its an easy change. for example on the vendor network tab if a user clicks a vendor node, maybe they can see an an aggregate of what was paid to the vendor, or a filtered list of line item payments that went to that vendor.

## Brief (fable-architect §1)
- **Interpretation.** On the Network tab's Money flow view, clicking any grouped node ("Top 28 individual donors", "Top 20 organization donors", "In-kind contributions", "Other transfers", "Other vendors", "Other independent spenders") opens a panel under the graph listing what is inside it: each member by name (linked to its page where one exists), its dollars into this entity and its row count, sorted by dollars, with a note on how many more exist beyond the graph's cap and a link to the Donors tab. Clicking a single node (a committee, a named transfer source, a named vendor, a candidate) lists its flows instead. On the Vendor network view, clicking a vendor lists which of the entity's committees paid it and how much; clicking a committee lists its vendors. Clicking the same node again, the background or Escape clears the panel, exactly as the ego graph's click focus (N19) already behaves. Nothing on other pages changes in this unit (the global networks/relationships pages get the shared renderer in plan step 7/9).
- **Scope.** Cross-Component: one feature (the Network tab) across the projection layer, the JSON route's cache revision, three static scripts, one template and their tests. No SQL, no schema, no new endpoint.
- **Approach.** Members are a projection: `money_flow()` already folds ego nodes into the class / "Other" nodes, so it also emits `members[aggregate_id]` from the same loop — no database read, same cache entry, same single-flight build. The three entity-view scripts share one small focus-panel helper (extracted from `ego_force.js`'s N19 list so the markup the existing tests pin is the contract). Vendor network reads its per-payer amounts from the edges it already has.
- **Success criteria.** (1) `money_flow(payload)["members"]` exists for every aggregate node and for no other node; each member list is sorted by amount desc, members are ego node ids, and the members' amounts sum to the aggregate node's amount (to the cent). (2) In the node harness, clicking an aggregate node renders the member list with links through `ctx.hrefs`; clicking a plain node renders its flows; second click / background / Escape clear; the vendor view lists payers per vendor and vendors per committee. (3) Existing suites green: `tests/test_entity_network.py`, `tests/test_entity_analytics_routes.py`, `tests/test_ego_focus_js.py`, `tests/test_graph_key.py`; `node --check` on every changed script; ruff clean. (4) `ENTITY_CACHE_REV` bumped so no cached projection without `members` is served; static `?v=` stamps bumped. (5) `docs/entity_networks.md` (N9) created with the view semantics + the drill-down contract.
- **Verification (minimum).** Fable observes red at D-M1; Fable re-runs the five suites + ruff + node checks at D-M2; Fable's own smoke on a local server from the clone (`network.json?view=money_flow` carries `members`; the tab page loads the new script); no specialist unless a finding warrants one.
- **Time budget.** 90 min builder time (range 60–120); thresholds 45 / 90 / 135 min. Milestones: D-M1 tests red (25 min) → D-M2 implementation green (+45) → D-M3 docs + stamps + report (+20).
- **Risks.** The ego payload caps donors at 40 / vendors 25 / transfers 15 / spenders 15 (`DEFAULT_CAPS`), so "who is in that 28" is complete for the graph but not for the entity — the panel must say so (`truncated` counts) and link onward; a member can appear in two lists (a donor with both 1A and 5A money) — allowed, each list carries that edge type's dollars; the `ego_force.js` extraction must keep the N19 markup byte-for-byte where the tests read it.
