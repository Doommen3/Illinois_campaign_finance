## Brief (fable-architect §1)
- **Interpretation.** Item 10 has a framework and then batches. *Framework:* (a) `docs/page_inventory.md` — every route the app serves (from `app.url_map`), grouped into classes of pages that draw the same figures from the same data path (one representative per class is evidence for the class); (b) `docs/data_integrity_checks.md` — the manual data-integrity checklist Devin runs (check id, what figure, how to recompute it independently, tolerance, sample rule, pass/fail), the sampling rule that says how big a sample is "big enough", the ordered batch plan (one fresh subagent per batch, each batch small enough to keep its context sharp) and a batch log. *Batches:* each one = a fresh agent that recomputes the class's figures from the source tables over a stratified sample, compares them with what the pages show, and writes a short report under `docs/audits/` plus the manual checks for that class. *Batch 1 = the donors class*, and its first finding is 8b: why the Network tab's in-kind "Democratic Party of Illinois" link lands on a donor page that lists one committee (Kendall County Democratic Party), whether it is system-wide, and how such issues are found in general. Nothing is fixed in this unit.
- **Scope.** Cross-Component for reading (routes, models, analytics, ETL compat views, the DB), Narrow for writing: three new documents, no application code, no DB writes.
- **Approach.** Two fresh contexts in parallel: **10-A** builds the framework from `url_map` + templates + the data dictionary; **10-B** runs batch 1 (donors) with the 8b root cause first. Independent recomputation means SQL over the source tables (`isbe_receipts` / `isbe_condensed_receipts` / the `bulk_receipts_clean` compat view), never the page's own query. Sampling rule (binary pass/fail per sampled member, zero failures observed): the 95% upper bound on the class failure rate ≈ 3/n — n = 30 → < 10 %, n = 60 → < 5 %, n = 300 → < 1 %; every class gets an n and the reason. The orchestrator re-runs the decisive queries before accepting a root cause.
- **Success criteria.** (1) `docs/page_inventory.md` lists every `url_map` rule verbatim exactly once, each in a class with its data path, figures and proposed checks. (2) `docs/data_integrity_checks.md` has the check format, the sampling rule, the batch plan (batch 1 = donors, then the other classes in an order that puts the most-read pages first) and a batch log; it links `docs/manual_tests.md` and is linked from it (item 9's M2 adds the link). (4) No private individual's name, address or donor key in any document (committees and organizations may be named). (5) `git status` shows only the new documents + this plan; `psql` ran read-only throughout (`PGOPTIONS='-c default_transaction_read_only=on'`).
