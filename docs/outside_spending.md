# Outside spending (ISBE D-2 Part 9 independent expenditures)

Added 2026-10-28 (plan `.claude/plans/outside-spending-drilldown.md`). Describes what is built.

## Where it shows

- **Candidate profile** `/candidates/<id>`: section "Outside spending (D-2 Part 9)" when any Part-9 row attaches to the candidate all-time. Supporting / Opposing / Total / row count follow the page window (`expended_date`); a by-spender table (committee → supporting, opposing, total, rows) and the link "All N line items" (N = rows in the window). An empty window keeps the section with "No outside spending in this window."
- **Line items** `/candidates/<id>/outside-spending`: one row per attributed expenditure — date, spender committee (link), For / Against, amount, share, purpose, payee, office and candidate name as filed, filing link. Filters `support_oppose` (S/O) and `committee_id` (spender); `sort` date|amount, `dir`; 100 rows per page; default scope all time, axis transaction date. 404 for an unknown candidate; an empty page (200) when nothing attaches.
- **State race detail** `/analytics/state-races/<race_key>`: the "Outside Spending Rows (D-2 Part 9)" table shows Candidate, Supporting, Opposing, Total, Rows; the candidate links to the line-item page with the window the row was computed over (`period=cycle:<C>` when the race window is the whole cycle, else `date_from`/`date_to`). The "Outside Spending (E)" card is the sum of the rows (support + oppose).

## Attribution rule (`database/outside_spending.py`, shared by the race builder)

ISBE Part-9 rows carry the targeted candidate as free text (`candidate_name`) with `supporting` / `opposing` flags and a free-text `office`; there is no candidate id. A row attaches to a candidate when:

1. **Name key** — `candidate_name_key`: strip `. , ' "`, upper-case, collapse spaces, drop trailing generational suffixes (`JR`, `SR`, `II`, `III`, `IV`, `V`) while more than two tokens remain, key = (first token, last token). "J.B. Pritzker" → ("JB", "PRITZKER"); "Michelle N. Pierre" and "Michelle Pierre" both → ("MICHELLE", "PIERRE"). Suffixes are ignored on both sides: ISBE keeps a suffix inside the candidate record's `last_name` ("Barberis, Jr") while filers write "John Barberis" or "John Barberis Jr", and all three → ("JOHN", "BARBERIS"); a two-token name keeps its last token ("Pat Jr" → ("PAT", "JR")). Fewer than two tokens ("Rauner") never matches.
2. **Split** — `split_candidate_names`: a string naming several candidates is split on `, ; / &` and the word `and`; each part is matched on its own and receives **amount / n** (`share`). Line items show the full amount and "1 of n". A part that is only a generational suffix (`JR`, `SR`, `II`, `III`, `IV`, `V` once `. , ' "` are stripped, as in "Carlos Rivas, Jr") or that repeats a part already kept (same text after that stripping, case folded) is dropped, so n counts the people the row names: "Pat Example, Jr" and "Pat Example and Pat Example" each give Pat Example the full amount. A single-comma "Last, First" filing is read as one name, written first-name-first: exactly one comma, a one-token left side, a one- or two-token right side that is not a bare suffix, no `; / &` and no word `and` — "Scherer, Sue" → "Sue Scherer", "Hanson, Matt R." → "Matt R. Hanson" (key ("MATT", "HANSON")); "Anderson, Sandra" reverses too (`and` inside a word is not the separator). Anything else splits as above: "Pat Example, Rae Rival" (two-token left side), "Hanson, Matt R Q" (three-token right side) and "Smith, John and Jones, Mary" stay several names.
3. **Cycle gate** — the row's cycle (`year + year % 2` of `expended_date`) must be one of the candidate's candidacy cycles (`isbe_candidacies`). On race pages the race's cycle is the window, so the gate is implicit. A candidate with no candidacies attaches nothing.
4. Archived rows (`archived = TRUE`) and every part other than `9%` never count. Every Part-9 row carries exactly one of the two flags (19,095 rows checked locally, 2026-10-28).

Coverage measured on all local Part-9 rows ($130.3M): exact full-string match (the rule before 2026-10-28) attributed 52.5 % of dollars; this rule attributed 82.2 % before the suffix and "Last, First" rules and attributes 83.6 % with them (re-measured 2026-10-28 with the repo's own matcher: 1,120 of 1,726 filed name strings, 16,945 of 19,095 rows, $109.0M). The 17.8 % left unattributed before those two rules ($23.2M) was, as the review's skeptic measured it: 10.8 pts keys matching no `isbe_candidates` record (nicknames such as "Chuy Garcia" and "Sam McCann", ballot questions, and, before the suffix rule, candidate records whose `last_name` carries a suffix — "John Barberis" vs "Barberis, Jr", ≈0.8 pt); 2.7 pts keys that exist only on records with no `isbe_candidacies` row — "Thomas L. Kilbride" ($3.4M in 2020) IS in `isbe_candidates` (twice), but the candidacies sit on the twin record "Tom Kilbride", whose page shows $929,750.67 of the $4.33M filed naming him, so this is a nickname/twin case, not a missing record; 2.5 pts single-token names ("Karmeier", "Rauner") and, before the "Last, First" rule, filings such as "Scherer, Sue" (≈0.6 pt); and 1.9 pts rows dated outside every candidacy cycle of their candidate (the cycle gate). Within a race one name key is one candidate (plan D4, reversed 2026-10-28): when two records of the race's candidacy feed share a key — one person registered under two candidate ids, e.g. "Margaret Croke" / "Margaret Noble Croke", Committeewoman Congressional 5, 2026 — the first record in feed order carries the race row and the twin gets none, so each Part-9 row counts once in the race total (keys are per race: another race keeps its own copy). The candidate page of each record still shows the rows, since a candidate page attaches by key + cycle.

Reconciliation invariant (tested): a race row's Total equals the candidate's line-item summary Total under the same window, to the cent.

## Performance

Candidate pages read `isbe_condensed_expenditures` directly with the predicate `d2_part like '9%' AND archived = FALSE` (lower-case `like` on purpose: `database/pg_compat.py` rewrites upper-case LIKE to ILIKE, which the partial index cannot serve), `expended_date` bounded by the candidate's cycle span (`(min cycle - 1)-01-01 .. (max cycle)-12-31`, a superset of the cycle gate) and a punctuation-stripped `like '%<LAST>%'` prefilter, then attribute in Python. The state race builder reads the matview the same way (predicate, race window, and for one race a `like ANY` prefilter on the race's last names); it falls back to the `bulk_expenditures_clean` compat view only where the matview does not exist (test fixtures). Through the compat view the race page's Part-9 statement took 1.1–2.1 s; on the matview it takes ~1 ms (local, 2026-10-28). Index: `idx_isbe_condensed_expenditures_part9_date ON isbe_condensed_expenditures (expended_date) WHERE d2_part LIKE '9%' AND archived = FALSE` (ETL DDL; 176 kB; EXPLAIN Index Scan Backward 6.7 ms for Pat Quinn's 3,298 rows with the cycle bound, ~33 ms without it, vs a 170–185 ms parallel seq scan before the index). Profile page cost: +15–50 ms. On prod the index is created by hand before the deploy restart: `CREATE INDEX CONCURRENTLY idx_isbe_condensed_expenditures_part9_date ON isbe_condensed_expenditures (expended_date) WHERE d2_part LIKE '9%' AND archived = FALSE;` (the ETL recreates it on the next import).

## Known limits

Nicknames and single-token names are not matched; the race builder's per-candidate rows depend on the candidacy feed (`isbe_race_candidacies`); federal candidates' Schedule E stays on `/federal-finance/`.

- Rows with three or more single-token parts, or a suffix after "Last, First" ("Scherer, Sue, Jr"), are not reversed and still attach to nobody.
- A name shared with another candidate in the same cycle, or one person running for several offices, gives each the same rows (race pages: every race of the cycle; profiles: every cycle of the candidate). The filed office is not used: check "Office (as filed)" and "Name (as filed)" on the line items (plan decision D11).
